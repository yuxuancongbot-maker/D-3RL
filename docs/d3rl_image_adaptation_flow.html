D3RL Image 适配数据流

核心原则：image 分支只在前端多做一次 MultiImageObsEncoder 编码， D3RL 的 scheduler / refiner 主逻辑仍然使用 [B, T, D] 特征序列；lowdim 旧路径保持原样。

Raw image / modality Encoded feature Source policy Ada scheduler Diffusion / SI refiner
Image path 新增适配路径
Input

Raw image obs

{image, agent_pos, ...}
形状如 [B,T,C,H,W] / [B,T,D]

Encode

MultiImageObsEncoder

把多相机图像和低维状态压成 obs_feat [B,T,D_feat]

System 1

Image source policy

Transformer 或 VAE source 使用 obs_feat 生成 init_action

Reuse

AdaScheduler

优先复用 source 返回的 obs_feat，预测 k ∈ {0,1,2,5}

System 2

Image refiner

refiner 用自己的 image encoder 构造 condition，对 init_action 做 DDIM/SI 精炼

Output

Env action

输出 refined_action；若 k=0 则直接执行 source action

代码里对应怎么走

  • 1ActionPredictorImagePolicy.predict_action() 先调用 encode_obs() 得到 obs_feat。
  • 2返回结果里带上 obs_feat，Ada-BRIDGER scheduler 可直接复用，不重复 encode。
  • 3AdaBridgerPolicy._get_scheduler_obs() 如果发现 obs_feat 维度匹配，就把它作为 scheduler 输入。
  • 4如果 feature 维度不匹配，则回退到 AdaSchedulerForImages，由 scheduler 自己 encode raw modality。
  • 5image refiner 分支使用 refine_policy.obs_encoder 生成 diffusion condition，保证和 refiner 训练方式一致。

关键保护

Lowdim 输入仍然是 {"obs": Tensor[B,T,D]}。 只要检测到这个格式，就直接走旧逻辑，不进入 image modality 分支。
  • ✓scheduler actor/critic 仍复用原来的 AdaScheduler。
  • ✓image 只新增 encoder wrapper 和 dict obs 处理。
  • ✓normalizer 缺少 image key 时保留原始 tensor，避免破坏旧 checkpoint。
